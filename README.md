<h2 align="center">About</h2>

I'm a software engineer who builds whole products and ships them wherever they need to run: web platforms in Next.js and Django, native desktop apps in Rust, mobile apps in Flutter, and developer tools for Python, Node.js, code editors and Windows. When a product needs AI, I build that part too, from LLM pipelines to computer vision that runs on the user's own machine.

I like understanding the layer below the one I'm working on, whether that's how a database lays documents out on disk or how an editor talks to a language server. Lately that has meant a lot of Rust: desktop apps, engines published to PyPI and npm, and a Python environment doctor that ships to four registries. The question I keep coming back to is the same one: what does it take to make this work outside a demo?

Most of what I build ends up shipped rather than shelved. Packages on PyPI and npm, extensions in editor marketplaces, installers people download.

<summary><b>&nbsp;Vigilo &nbsp;·&nbsp; Webcam Proctoring for Online Exams (demo on request)</b></summary>
<br/>

Vigilo is webcam proctoring for online exams. It watches for the things that matter during a test: nobody in front of the camera, a second person in the frame, a phone in shot, a head turned away, eyes off the screen, and whether the person sitting the exam is still the one who enrolled.

It reports violations rather than raw readings. Each one has to hold for a set time before it's raised, so a blink or a glance at the keyboard doesn't become an alert a proctor has to dismiss, and each carries a severity from low to critical so a reviewer can triage.

- Every threshold, hold time and severity is adjustable in the app, so it can be stricter for a high-stakes certification and more forgiving for a practice quiz.
- Detection runs on the candidate's own machine, on the CPU. No GPU is needed and no video is sent to a server.
- Installers for Windows, macOS on Apple Silicon and Linux include everything it needs, so there's nothing else to install first.

**Stack** &nbsp;·&nbsp; Rust, Tauri, ONNX Runtime

**Links** &nbsp;·&nbsp; [Request a demo](https://abdullah-masood.vercel.app/?demo=vigilo#contact) &nbsp;·&nbsp; [Overview](https://abdullah-masood.vercel.app/projects/vigilo) &nbsp;·&nbsp; [vigilo-stream (Python)](https://github.com/Abdullah-Masood-05/vigilo-stream) &nbsp;·&nbsp; [vigilo-wasm (browser)](https://github.com/Abdullah-Masood-05/vigilo-wasm)

Vigilo isn't publicly downloadable and its source is private. If you run online exams and want to see it working, [request a demo](https://abdullah-masood.vercel.app/?demo=vigilo#contact) and I'll set one up. For developers, the detection engine is also published as Python bindings and as a WebAssembly build that runs in a browser tab.

<details>
<summary><b>&nbsp;PyPilot &nbsp;·&nbsp; Python Environment Doctor (Rust, shipped to four registries)</b></summary>
<br/>

A package's `requires_python` is often incomplete. mediapipe 0.10.14 doesn't declare it at all, yet only ships wheels for cp39 through cp312, so on 3.13 pip goes hunting for a source distribution that doesn't exist and stops with an error that never once mentions the Python version.

PyPilot reads both signals. It takes `requires_python` as a starting range, then intersects it with the interpreter versions that actually have prebuilt wheels for your OS and CPU architecture, repeated across every dependency in the workspace. What survives is the set of interpreters that can run the whole project. When that set comes back empty, it names the packages whose constraints collide, which is the thing pip never tells you and the reason dependency conflicts eat an afternoon. `pypilot explain` shows, platform by platform, what rules out each Python version.

It also catches the failures that happen after a successful install. mediapipe 0.10.35 installs fine and then crashes on `module 'mediapipe' has no attribute 'solutions'` because Google removed the legacy API, so PyPilot inspects the installed package on disk and flags `mp.solutions` in the editor while you're writing it. A table of known breakages, refreshed weekly, covers more of what metadata doesn't show: numpy 2 breaking older compiled packages, uncapped dependencies that later removed an API (markupsafe and jinja2, werkzeug and flask), and removed APIs in your own code such as `np.float` or pandas 2's `DataFrame.append`, reported by file and line.

For GPU frameworks it reads `nvidia-smi`, maps the driver to the newest CUDA runtime it supports and the GPU to the CUDA range it needs, and installs the matching torch build (`cu124`, `cu132` and so on). Environments are built with uv by default, or plain venv and pip if you prefer. When a package needs native libraries pip can't supply, such as GDAL or PROJ, PyPilot suggests pixi, and `pypilot migrate-to-pixi` previews the `pixi.toml` before writing anything.

Since 1.4, `doctor --fix` repairs only what it found instead of rebuilding the environment. A package that drifted from the lock gets `uv sync --locked`, a stale lock gets `uv lock`, a damaged venv is rebuilt on the Python it already had, an unsatisfiable pin gets a relaxed one that's checked with uv before it's offered, and an import missing from the dependencies is added under its distribution name (`sklearn` becomes scikit-learn). Across 54 deliberately broken environments, 45 now get the right targeted fix where 13 did before, none get a wrong fix where 9 did, and the other nine are reported with what to change.

Everything resolves from PyPI metadata and bundled lookup tables. No AI, no API keys, no external services.

**Stack** &nbsp;·&nbsp; Rust, LSP, WebAssembly (wasm32-wasip2), TypeScript, Bun, uv, pixi

**Repos** &nbsp;·&nbsp; [pypilot (Zed + engine)](https://github.com/pypilot-dev/pypilot) &nbsp;·&nbsp; [pypilot-vscode](https://github.com/pypilot-dev/pypilot-vscode) &nbsp;·&nbsp; [pypilot-pip (CLI)](https://github.com/pypilot-dev/pypilot-pip) &nbsp;·&nbsp; [Docs](https://pypilot-dev.github.io/pypilot/)

One Rust binary, four ways to get it: `pip install pypilot-cli`, which bundles the engine on Linux, macOS and Windows, the VS Code Marketplace, Open VSX for VSCodium and Cursor, and the Zed extension registry. The editor extensions hold no business logic, so churn in an editor's extension API can't break environment resolution.

<summary><b>&nbsp;BisonDB + Prairie &nbsp;·&nbsp; A Document Database Built From Scratch (C++20)</b></summary>
<br/>

A document database written in C++20 with no third-party storage or networking libraries. Hardened BSON codec, append-only collection store, hand-written on-disk B+Tree, an index-aware query planner with explain plans, and a TCP daemon speaking a documented framed-BSON protocol with TLS and Argon2id authentication.

Prairie is the companion desktop client, a Compass-style GUI built with Tauri 2 and React. It browses documents, runs filters with explain plans, and manages indexes. It bundles the `bisond` engine as a sidecar, so it can open a local database directory with no daemon to start first.

**Stack** &nbsp;·&nbsp; C++20, custom BSON, on-disk B+Tree, TCP, TLS 1.2, Argon2id, Tauri 2, React

**Repos** &nbsp;·&nbsp; [Bisondb](https://github.com/Abdullah-Masood-05/Bisondb) &nbsp;·&nbsp; [Prairie](https://github.com/Abdullah-Masood-05/Prairie) &nbsp;·&nbsp; [Docs site](https://abdullah-masood-05.github.io/bisondb-site/)

This is the project I point to when someone asks whether I understand what a database does under the hood. Every layer, from how a document hits the disk to how an index lookup resolves, is something I wrote and can explain.

<summary><b>&nbsp;NoirPlayer &nbsp;·&nbsp; Music Player for Android and Desktop</b></summary>
<br/>

A dark-themed music player that started on Android and got rebuilt for the desktop. My most-starred repo.

The Flutter app plays your local library through `on_audio_query` against the device MediaStore, with background playback wired through `audio_service` so the notification, lock screen, and headset buttons all work the way people expect. `just_audio` handles decoding and gapless transitions, and its `AndroidEqualizer` gave a native per-band equalizer without bolting on a separate audio-effects plugin. A Discover tab chains Last.fm search to a YouTube video match to an MP3 resolver, downloading into the local library.

The desktop version is a from-scratch Rust rebuild on GPUI Kit, not a stretched phone layout. Navigation rail, dockable queue, transport bar. Lofty scans multiple library folders recursively and reads embedded artwork, Rodio handles playback with ALAC and AIFF decoding, and there's a 5-band graphic equalizer from 60 Hz to 14 kHz.

**Stack** &nbsp;·&nbsp; Flutter, Dart, audio_service, just_audio &nbsp;/&nbsp; Rust, GPUI Kit, Rodio, Lofty

**Repos** &nbsp;·&nbsp; [NoirPlayer (Android)](https://github.com/Abdullah-Masood-05/NoirPlayer) &nbsp;·&nbsp; [noir-player-desktop-app](https://github.com/Abdullah-Masood-05/noir-player-desktop-app)

The desktop build ships per-platform installers rather than one generic bundle: WiX MSI and NSIS on Windows, a `.dmg` on macOS, and `.deb`, `.rpm`, and `.pkg.tar.zst` on Linux, each with a SHA-256 sidecar.
